# Hirebase capability inventory

Backend maintainer reference, not an end-user screen. Documentation reviewed 11 November 2026. Live-ready means implemented, not authenticated-live-verified. All samples are synthetic. Owner-only operations require local configuration; sample-only and unavailable operations cannot be unlocked by owner mode.

## Job discovery

| Operation                                                                            | Endpoint                      | Access | Cost / caveat                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------ | ----------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Search jobs](https://www.hirebase.org/docs/api-reference/jobs/search-post)          | `POST /v2/jobs/search`        | live   | 1 unit / job. Strict filters. These presets are unverified here. Earlier lab tests found Hong Kong location mismatches; verify raw and normalized locations before relying on coverage. Exact tags come from Reference data. technology_slugs is not available. |
| [Estimate search cost](https://www.hirebase.org/docs/api-reference/jobs/estimate)    | `POST /v2/jobs/estimate`      | live   | 0 units. Same filter shape as text search. Cost is the number of billable jobs for this request.                                                                                                                                                                |
| [Neural search](https://www.hirebase.org/docs/api-reference/jobs/neural-search-post) | `POST /v2/jobs/neural-search` | live   | 1 unit / job. Relative dates and nested pagination. Counts cap at 2,500. Provider ignores inner typos; this playground rejects them. Provider does not publish a limit maximum; playground cap is 100.                                                          |
| [Job by ID](https://www.hirebase.org/docs/api-reference/jobs/get-by-id)              | `GET /v2/jobs/{job_id}`       | live   | 1 job unit. Requires an API key. Availability depends on your account.                                                                                                                                                                                          |
| [Look up posting URLs](https://www.hirebase.org/docs/api-reference/jobs/lookup)      | `POST /v2/jobs/lookup`        | live   | 1 unit / found job. Replace the illustrative URL with real posting URLs. Up to 100 URLs; only found jobs are billed.                                                                                                                                            |

## Resumes

| Operation                                                                        | Endpoint                             | Access | Cost / caveat                                                                                                                                                                                                   |
| -------------------------------------------------------------------------------- | ------------------------------------ | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Upload resume](https://www.hirebase.org/docs/api-reference/resumes/upload)      | `POST /v2/resumes/upload/`           | owner  | Account-dependent. Owner only. Stores the resume with Hirebase. Exactly one PDF, DOC/DOCX, TXT or HTML file, maximum 5 MB. Correct MIME type required.                                                          |
| [Parse stored resume](https://www.hirebase.org/docs/api-reference/resumes/parse) | `POST /v2/resumes/{resume_id}/parse` | owner  | Metered by provider. Owner only. Parses and updates the uploaded record. Its ID can be used as vector.artifact_id.                                                                                              |
| [Get stored resume](https://www.hirebase.org/docs/api-reference/resumes/get)     | `GET /v2/resumes/{resume_id}`        | owner  | Metered by provider. Owner only. Sensitive personal data; responses remain in memory, with contact fields redacted.                                                                                             |
| [Embed resume](https://www.hirebase.org/docs/api-reference/resumes/embed-post)   | `POST /v2/resumes/embed`             | owner  | Metered by provider. Owner only. Stateless processing; no stored artifact ID. Docs conflict on whether parsed resume is returned with embedding. Raw view preserves actual fields; contact fields are redacted. |
